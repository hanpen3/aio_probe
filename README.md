# AI要約のリンク調査キット（WD ハッカソン用）

Google で検索したときの **AI要約（AI による概要）** に出てくるリンクと、**通常の検索結果の上位10件**を取り出して比べ、**Google Safe Browsing（GSB）** で悪性かどうかを調べるための道具です。

自分のブラウザで検索して保存したページを、プログラムが読みます。

## 1. 用意するもの

- **Python 3.7 以降**。追加のインストールは要りません。
  - 確かめ方：Mac は `python3 --version`、Windows は `py --version`
- **WarpDrive（WD）の拡張機能を入れていないブラウザ**。WD のデータを汚さないためです（「4. 守ってほしいこと」を参照）。
- **GSB の API キー**（GSB で調べる場合だけ）。無料です（営利目的でない用途に限ります）。
  - 取り方：Google Cloud のコンソールでプロジェクトを作る → 「Safe Browsing API」を有効にする → 「認証情報」で API キーを作る → キーの使える API を Safe Browsing API だけに制限する

## 2. フォルダの構成

```
aio_probe/
├── README.md          ← このファイル
├── html_probe.py      ← 保存したページから、AI要約と上位10件のリンクを取り出して比べる
├── gsb_check.py       ← 取り出したリンクを GSB で調べる
├── inspect_html.py    ← （確認用）保存したページの中身を、上から順に印を付けて表示する
├── html/              ← ここに、保存した検索結果のページ（.html）を入れる
└── out/               ← 結果がここに保存される（自動で作られる）
```

作り方（Mac）：

```bash
mkdir -p ~/aio_probe/html ~/aio_probe/out
# 配られた html_probe.py・gsb_check.py・inspect_html.py・README.md を ~/aio_probe/ に置く
cd ~/aio_probe
```

## 3. API キーの置き場所

キーは**作業用フォルダの外**、自分のホームフォルダに置きます。ファイルには**キーの文字列だけを1行**書いてください（`API_KEY=` などは付けない）。

```bash
nano ~/.gsb_key          # キーを貼る → Ctrl+O、Enter で保存 → Ctrl+X で閉じる
chmod 600 ~/.gsb_key     # 自分だけが読めるようにする
```

- 別の場所に置いた場合は、`--key-file 場所` で指定できます。
- 環境変数 `GSB_API_KEY` に入れても使えます（ファイルより優先されます）。
- キーは、チャットやメール、共有フォルダに貼らないでください。プログラムは、キーを画面にもファイルにも出しません。

## 4. 守ってほしいこと（安全とデータのため）

- **WD を入れたブラウザで検索しない。** WD の利用ログの分析に、ハッカソン用の検索が混ざってしまいます。WD を入れていないブラウザか、Chrome のゲストモードなどを使ってください。
- **普段のアカウントにログインしないで検索する**のがおすすめです。検索結果が個人に合わせて変わるのを防ぐためです。
- **検索結果やAI要約のリンクは、押して開かない。** 悪性のサイトが混ざっている可能性があります。プログラムは、リンク先には一切アクセスしません。`report.html` の URL も押せない文字として表示し、悪性と判定されたものは `hxxps://example[.]com` のように崩して表示します。

## 5. 使い方

### 手順1：検索してページを保存する

1. WD の無いブラウザで Google を開き、検索する。
2. **AI要約が最後まで表示されるのを待つ。** 「生成中」のまま保存すると、中身が入りません。
3. ページを保存する：Mac は `Cmd+S`、Windows は `Ctrl+S`。形式は「ウェブページ、HTML のみ」でも「ウェブページ、完全」でも構いません。
4. 保存した `.html` を `aio_probe/html/` に入れる。
   - ファイル名は何でも構いません。英数字の名前（例：`flu_symptoms.html`）にするとコマンドで扱いやすいです。
   - 検索語は、ページの題名（「〇〇 - Google 検索」）から自動で読み取ります。
   - 「ウェブページ、完全」で保存したときにできる `…_files` フォルダは要りません。

### 手順2：AI要約と上位10件を取り出して比べる

```bash
cd ~/aio_probe
python3 html_probe.py
```

`html/` の中の `.html` を全部読み、ページごとに1行ずつ結果を表示します。表示される内容は、AI要約の有無、AI要約のリンク数、上位10件の数、共通の数です。結果は `out/` に保存されます。

Windows では、`python3` の代わりに `py` を使ってください（例：`py html_probe.py`）。

### 手順3：GSB で調べる

```bash
python3 gsb_check.py --dry-run     # 送る件数だけ確かめる（何も送らない）
python3 gsb_check.py               # 調べる
```

悪性と判定されたものの数と、崩した URL が表示されます。`out/report.html` も GSB の結果を入れて作り直されます。

### 手順4：結果を見る

```bash
open out/report.html       # Mac。Windows は start out\report.html
```

- 上の表：検索ごとの要点
- 各検索の詳細（押すと開く）：AI要約の文章と、リンクの一覧
  - 赤い行：GSB で悪性と判定されたもの
  - 青い行：AI要約と上位10件で共通の URL

### （確認用）保存したページの中身を見る

AI要約がうまく取り出せないときに、ページの中身を上から順に表示します。

```bash
python3 inspect_html.py html/flu_symptoms.html --around H | less
```

AI要約に関係する行に、次の印が付きます。

- H：見出し
- R：「AI モードの回答:」
- M：もっと見る
- W：ウェブ検索結果
- Q：関連する質問
- X：エラーの文言
- E1〜E4：末尾の注意書き
- G：Google の転送用のリンク

## 6. 変えられる設定

**html_probe.py**

| 設定 | 既定 | 意味 |
|---|---|---|
| `--html-dir フォルダ` | `html` | 保存したページを置いたフォルダ |
| `--out フォルダ` | `out` | 結果の保存先。人や日ごとに分けたいときに変える |
| `--top 数` | `10` | 通常の検索結果を上から何件取るか |
| `--max-items 数` | `300` | AI要約の範囲の上限の行数。超えると「範囲が不確か（too_long）」として取り出さない |

**gsb_check.py**

| 設定 | 既定 | 意味 |
|---|---|---|
| `--out フォルダ` | `out` | html_probe.py の結果のフォルダ |
| `--key-file 場所` | `~/.gsb_key` | GSB のキーのファイル |
| `--dry-run` | （なし） | 問い合わせずに、送る件数だけ表示する |

例：人ごとに分ける場合。

```bash
python3 html_probe.py --html-dir html_sato --out out_sato
python3 gsb_check.py --out out_sato
```

## 7. 結果のファイル（`out/` の中）

| ファイル | 中身 |
|---|---|
| `searches.tsv` | ページごとの要点（Excel で開けます） |
| `links.tsv` | リンクごとの詳細 |
| `aio_text.jsonl` | AI要約の範囲の文章（ページごとに1行） |
| `gsb_results.tsv` | GSB に送った URL ごとの判定と、問い合わせた日時（UTC） |
| `report.html` | 一覧（ブラウザで開く） |

**`searches.tsv` の列**

- `id`：ファイル名
- `query`：検索語
- `aio`：AI要約の有無（あり／なし）
- `status`：判定
  - `aio`：AI要約あり
  - `none`：AI要約なし
  - `unclosed`：終わりが見つからない
  - `component`：中身の無い部品だけ
  - `too_long`：範囲が長すぎる
- `end`：AI要約の終わりの目印
  - `M`：もっと見る
  - `W`：ウェブ検索結果
  - `E1`〜`E4`：末尾の注意書き
- `items`：AI要約の範囲の行数
- `aio_links`／`aio_domains`：AI要約のリンク数／ドメインの種類数
- `organic`／`organic_domains`：上位10件のリンク数／ドメインの種類数
- `common_url`／`common_domain`：AI要約と上位10件で共通の URL の数／ドメインの数
- `gen`：「生成中」の表示が残っていたら 1

**`links.tsv` の列**

- `source`：どこのリンクか
  - `aio`：AI要約
  - `organic`：上位10件
- `rank`：順番
- `url`：リンクの URL（`#` 以降は除く）
- `gsb_url`：GSB に送った形（クエリと `#` を除いたもの）
- `domain`：ドメイン（先頭の `www.` は除く）
- `in_top10_url`／`in_top10_domain`：AI要約のリンクが、上位10件にも URL／ドメインとしてあるか（1／0）
- `in_aio_url`／`in_aio_domain`：上位10件のリンクが、AI要約にもあるか（1／0）
- `text`：リンクの文字（ページ名やサイト名）

## 8. 取り出しの規則

- **AI要約の範囲**
  - 始まり：「関連する質問」より前にある最初の「AI による概要」の見出し
  - 終わり：その後に最初に出てくる「もっと見る」「ウェブ検索結果」、または末尾の注意書き
  - 「関連する質問」の中の AI の回答は対象外です。
- **AI要約のリンク**
  - 範囲の中の、外部のサイトへのリンクです。
  - Google 自身のリンク（ヘルプなど）は除きます。
  - `#` 以降を除いた URL が同じものは、1回だけ数えます。
- **上位10件**
  - 対象：最初の「ウェブ検索結果」より後ろのリンクのうち、すぐ後ろに「https://ホスト名」というサイトの住所が表示されているもの
  - これで、検索結果の1件ずつのリンクだけを取り、関連する質問・動画・画像などの枠のリンクは入れません。
- **共通**
  - URL：クエリ・`#`・先頭の `www.`・末尾の `/` を除いて同じなら共通
  - ドメイン：ホスト名が同じなら共通

## 9. 注意と限界

- **GSB の判定は、問い合わせた時点のもの**です。結果を記録するときは、`gsb_results.tsv` の日時も一緒に残してください。
- **悪性と判定されるものは、とても少ない**と考えられます。0件でも、プログラムの誤りとは限りません。動作の確認には、Google が用意したテスト用の URL（`http://malware.testing.google.test/testing/malware/`）が使えます。これは GSB に問い合わせるための文字列で、開くページではありません。
- **Google の画面は、時期や検索語によって形が変わります。** AI要約があるのに「なし」や `unclosed` になったら、`inspect_html.py` で中身を確かめてください。
- 保存したページは、**その人のその時の画面**です。同じ検索語でも、人・時刻・場所によって結果は変わります。
- 検索語やページの中身には、個人の関心が表れます。結果のファイルを共有するときは、扱いに気を付けてください。

## 10. うまくいかないとき

| 症状 | 確かめること |
|---|---|
| `html に .html のファイルがありません` | ページを `html/` に入れたか。`--html-dir` の指定が合っているか |
| AI要約があるのに「なし」 | AI要約が表示し終わってから保存したか。`inspect_html.py --around H` で、見出し（H）があるか |
| `GSB のキーがありません` | `~/.gsb_key` があるか。中身がキーの文字列だけか |
| `中止：返答 400` や `返答 403` | キーが正しいか。Safe Browsing API を有効にしたか。キーに IP アドレスの制限をかけていないか |
| `接続できませんでした` | インターネットに接続できるか |
